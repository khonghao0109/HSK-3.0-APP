# ADR-006: Hermetic Media Operations and Private Metrics

Status: Accepted for code; live environment approval remains external.

## Decision

Media metrics use a dedicated listener on port 9464 with exact `GET /metrics` and
current/previous bearer authentication. The public API and Nginx edge deny `/metrics`
and the legacy metrics namespace. Prometheus discovers ready backend pods, scrapes
each replica directly, and is authorized by NetworkPolicy plus Istio STRICT mTLS and
workload identity. No public Nest controller exposes metrics.

Prometheus, Alertmanager and Grafana V1 are single-replica with explicit RWO PVCs
and `Recreate` rollout. This avoids duplicate notifications and multi-attach
deadlock at the cost of a brief declared monitoring gap. HA requires a later
clustering/dedup ADR. Prometheus retains 32 days on a 50 GiB PVC so 28-day SLI
queries are possible, but this is local retention rather than a durable backup.

Operational tools are selected from a typed Darwin-arm64/Linux-amd64 manifest,
checksum-verified before safe extraction, exact-version probed, and functionally
exercised. Validators report independent `PASS`, `FAIL_INTERNAL`, or
`BLOCKED_EXTERNAL` outcomes and write sanitized JSON/JUnit evidence.

Only the `release-linux-amd64` profile is release-authoritative, and it must run on
an actual Linux x86_64 kernel. Darwin arm64 is a reference profile, never an
equivalent release proof. OCI indexes and Linux amd64 children are pinned
separately.

### OCI release-acceptance trust boundary

The selected model is Option C: an HSK-owned, keyless-signed release-acceptance
manifest. It is deliberately **not** upstream publisher provenance. Read-only
registry and Cosign inspection on 2026-08-22 found no upstream image signature,
SBOM attestation or referrer for the exact selected index/child pairs. HSK therefore
must not use its own workflow identity as though it had signed artifacts in an
upstream repository.

The acceptance manifest binds the current HSK commit, Git tree, rendered release
content digest and release tag to all of the following for each image:

It also binds each observed source tag/object/commit as metadata, the exact SPDX
JSON bytes generated by pinned Syft, the exact Grype report and database identity,
and the exact license report/policy. A source tag signature is useful corroboration
but is never treated as image provenance. Critical or High findings and unknown or
denied licenses fail closed unless a finding-specific waiver has an owner, reason and
unexpired expiry.

The only accepted issuer is
`https://token.actions.githubusercontent.com`. The exact allowlisted certificate
identity is
`https://github.com/khonghao0109/HSK-3.0-APP/.github/workflows/media-release-evidence.yml@refs/tags/v3.0.0`.
Every detached-bundle verification also pins the GitHub certificate claims to
workflow name `Media release evidence`, repository
`khonghao0109/HSK-3.0-APP`, ref `refs/tags/v3.0.0`, trigger `push` and the exact
release commit SHA. The path/tag identity alone is insufficient because a moved
tag must not make a signature from another workflow commit acceptable.
Empty, wildcard, branch-scoped, wrong-repository or otherwise broadened identities
are invalid configuration, not external evidence gaps. Security Platform owns the
allowlist and scanner/license policy; Release Engineering owns the protected tag
workflow and retained artifact. Rotation requires a reviewed repository change to
the exact tag-scoped identity, fresh evidence for the replacement release and
revocation/removal of the old allowlist. Re-running or editing an old manifest does
not rotate trust.

The threat addressed is substitution or tampering after image selection: the
validator first verifies the detached Sigstore bundle and exact certificate facts,
then parses the same signed bytes, then checks all report hashes and release/image
bindings. It does not claim to protect against a malicious upstream publisher before
HSK inspection, a compromised approved HSK workflow, or a vulnerability disclosed
after the scanner database timestamp. Missing trusted bytes are
`BLOCKED_EXTERNAL`; malformed, tampered, mismatched or policy-violating supplied
bytes are non-green; validator/repository defects are `FAIL_INTERNAL`. Until the
protected workflow has produced and retained current evidence for all three images,
the supply-chain prerequisite remains `BLOCKED_EXTERNAL` and production release is
not approved.

The verifier workflow never signs a caller-supplied manifest, report, capacity
record, live-rehearsal package or prerequisite inventory. Doing so before semantic
validation would launder self-declared claims into the trusted HSK identity. It
accepts only a pre-existing payload/bundle pair, verifies that bundle before parsing,
and retains the non-green result when the pair is absent. Successfully verified
payload and bundle snapshots are copied into the protected evidence tree before
their private verification directory is removed, so the final archive can repeat
detached verification.

The verifier supports one pre-signed live-rehearsal package for exactly
`media-live-s3-provider`, `media-live-clamav`,
`media-deployed-proxy-mesh-policy`, `media-production-alert-delivery`,
`media-backend-replica-discovery` and
`media-secret-manager-workload-identity`. The protected runner supplies the package
only through `MEDIA_OPS_LIVE_REHEARSAL_EVIDENCE_JSON`,
`MEDIA_OPS_LIVE_REHEARSAL_EVIDENCE_BUNDLE` and
`MEDIA_OPS_LIVE_REHEARSAL_EVIDENCE_ROOT`. It reads bounded, single-link regular files
under the canonical root and verifies the detached bundle against the same exact
tag-scoped issuer, identity, workflow name, repository, ref, trigger and release SHA
used by the other release inputs before parsing JSON.

The aggregate manifest is exactly
`hsk-media-live-production-evidence-v1`: it binds the current Git commit, Git tree and
release-content digest; canonical observation and expiry times; and one environment
identity made from cluster and namespace SHA-256 identities, an exact
`sha256:<64>` deployment revision and
`sha256("hsk-media-live-environment-v1\0" + cluster + "\0" + namespace + "\0" +
revision)`. Observation may be at most 60 seconds in the future, and the observation,
expiry and current validation time must all fit within the seven-day V1 freshness
window. Its artifact registry must contain all and only the six IDs, with one
distinct safe relative path and raw SHA-256 per ID. Each bounded per-ID JSON record
must repeat the exact prerequisite/evidence type, trusted producer, release binding,
environment and freshness; carry `status: PASS`, a credential-free evidence URI,
hashed command provenance and sanitized log; and satisfy the prerequisite's complete
semantic check registry with exact `{id, status: PASS, evidenceSha256}` records and no
missing, extra or duplicate check IDs. Evidence URIs must also be distinct across the
six records. Accepted bytes are retained as
`live-rehearsals/manifest.json`, `live-rehearsals/manifest.sigstore.json` and one
normalized `live-rehearsals/artifacts/<prerequisite-id>.json` record per ID under the
protected `trusted-inputs` tree.

A missing package, bundle, root or referenced record is `BLOCKED_EXTERNAL`. An
externally supplied package that is partial, stale, tampered, path-unsafe, incorrectly
bound or semantically incomplete is also rejected as `BLOCKED_EXTERNAL` and cannot
register a PASS; a missing/incorrect repository verifier registration is
`FAIL_INTERNAL`. The current `v3.0.0` workflow
contains no collector capable of minting this package or the other release bundles.
A future external collector must execute the pinned scanners and live rehearsals
itself, then sign the inspected results under the separately reviewed exact
tag-scoped identity. No such real collector or evidence exists in this closeout, so
all affected production prerequisites remain `BLOCKED_EXTERNAL`.

The immutable archive attestation is intentionally a post-gate operation, not a
pre-existing input to the same run. The runner emits
`postGateAttestationReady=true` only when every validator has passed except the
single `media-immutable-evidence-attestation` result, which must still be
`BLOCKED_EXTERNAL`. The protected workflow may then attest the already frozen tar;
every other external block or any internal failure prevents that transition. This
breaks the self-dependency without reporting the not-yet-created attestation as
PASS inside the runner.

Alert and dashboard sources contain `__MEDIA_RUNBOOK_URL__`; deployment must use the
deterministic renderer with a real credential-free HTTPS URL. Source artifacts with
the marker are not deploy-ready. Reachability is an external gate and is never
inferred from a placeholder.

Signed-content request counters begin at the public service boundary so invalid-grant
volume remains observable. The availability SLI excludes terminal `invalid_grant`
from its eligible denominator and failure numerator; otherwise an anonymous caller
could consume the 99.9% error budget with forged or expired grants. Provider outage,
provider mismatch, integrity failure and started-without-terminal deficits still burn
the SLO. Promtool fixtures cover invalid-grant spray, eligible failures, no traffic,
multiple replicas, pod replacement and recovery.

Ingestion availability has the same eligibility boundary: terminal `rejected` and
`disabled` outcomes remain observable but are removed from the valid-ingestion
denominator and failure numerator. Only terminal `failed` and `cleanup_required`
outcomes burn this SLO, while a positive all-started-minus-all-terminals deficit still
burns it. Promtool fixtures cover rejected/disabled spray and eligible
failed/cleanup-required burns.

## Consequences

- Token rotation requires backend rollout because secrets enter through environment
  variables; it is not projected-file hot reload.
- Application readiness, liveness and startup remain owned by the backend
  Deployment. The portable metrics patch adds none of those handlers; local
  strategic-merge rehearsal must prove every existing startup handler is preserved
  exactly and never combined with a second handler. Because backend and monitoring
  workloads use STRICT mTLS, all pod templates explicitly enable Istio HTTP probe
  rewriting; removing that annotation is a validation failure.
- Grafana is deliberately a private authenticated API-only artifact in V1. The
  allowlisted `hsk-media-operator` workload identity may use health, dashboard and
  datasource APIs; no browser UI path is claimed. Human browser access requires a
  separately designed authenticated access gateway and a later policy change.
- Dashboard panels bind the fixed provisioned datasource UID
  `hsk-media-prometheus`; the validator provisions and reads back that exact UID
  without rewriting a template variable.
- Capacity must be measured before rollout: `required GiB = ingest bytes/day × 32 ×
1.25`. Abort when projected use exceeds 80% of 50 GiB. PVC binding, snapshot
  backup, restore rehearsal and StorageClass expansion remain live gates; loss of
  this single PVC can erase the retained SLI history. The Linux release profile
  accepts only fresh, release-bound machine evidence for those live facts; absent
  evidence is a non-green external block.
- The internal gate proves disposable Grafana query execution and Prometheus-to-
  Alertmanager page/ticket firing/resolved delivery using repository configs. SRE
  must separately prove PVC binding, deployed service-mesh policy, real runbook
  reachability and production notification delivery in the target environment.
- No historical migration is changed. Migration 18 supplies stable lifecycle
  timestamps and migration 19 hardens cleanup audit integrity; immutable history
  and cleanup evidence remain retained.
